# Eleventh reference: technical acceptance gates

Prepared from retained metadata, source text and installed codec source only. No candidate scan/label/optical arrays, network requests, model construction or model calls were used. Root owns reference roles and scientific decisions. Passing decoder fixtures alone does not resolve the acquisition contract.

## 1. Coordinate and depth contract before acquisition

- Pin exact specimen/alias, scan, segment, publication date, array level and metadata bytes for every requested asset. Bind the source writer/transfer/exporter revision; retain any dirty-revision limitation. Matching shapes or resolutions establishes compatibility, not registration.
- Write the complete directed mapping: original annotation raster → transfer canvas → published label pixels → selected surface-volume pixels. For each offset/affine, state axis order, units, level, sign, composition order, sample convention and **whether the writer already applied it**. Store the resulting mapping once. An offset retained as provenance is not automatically an extra read-time shift; never add both a total offset and its residual without an explicit writer contract.
- PHerc0009B demonstrates why axis names matter: the retained surface `canvas_size` is `[20520,25360]` (XY), while the label group's is `[25360,20520]` (YX). Its arrays are ZYX and YX respectively. Use named axes, not this attribute's positional appearance.
- Confirm level construction and sampling phase: retained label convention says decimation `[::2,::2]`, while surface metadata says XY mean downsampling. Equal level-2 spacing 9.604 µm alone does not prove matching pixel-center conventions. Follow the actual export/read contract; do not invent a half-pixel correction or align by maximizing prediction agreement.
- Record the depth coordinate of each rendered plane, reference surface/annotation plane, normal direction and whether `flip_normals` was already applied. `109` planes, `slice_step=1`, scan top-to-bottom direction and zero OME translation do not by themselves identify the ink surface or authorize `[13,97)` pooling. The rendered Z axis is a surface-normal sampling axis, not automatically native CT Z.
- Any pooling/window must follow that physical mapping: explicit original-plane indices, grouping weights, resulting sample centers/spacing, endpoint behavior, dtype/rounding, and final 17-plane order. Reject out-of-range or unsupported sampling. A label-only window or later intensity acquisition must be frozen as its own permitted stage; unresolved depth is not silently completed by array shape.

## 2. Annotation participation and unknown values

- Resolve actual per-asset metadata and allowed encodings for ink, supervision, validation and mapping validity. Do not assume ink `{0,1}` versus `{0,255}`, or infer a binary threshold from dtype alone. Validate the declared values after the separately authorized bounded decode.
- Keep label value and label participation separate. `ink == 0` is a negative only inside the explicitly chosen supervision/validation and mapping-validity domain. Unsupervised, unmapped, unfetched, out-of-bounds or failed-decoding pixels are not negative labels.
- Preserve S and V independently; record whether V is a subset of S, disjoint or another convention. Apply only the frozen evaluation/training role, not an assumed subtraction rule borrowed from another dataset.
- Preserve mapping-validity codes `0=unmapped`, `128=seam-filled`, `255=measured` as distinct values. State which participate and retain separate counts; `validity > 0` must not silently claim measured mapping. Apply crop/transform operations identically to labels and all participation masks. Use the declared discrete-label resampling rule, never interpolate categorical values as intensities.
- Bound label-only selection, candidate enumeration, eligibility/class-count rules and tie-breaking before predictions. Preserve rejected candidate reasons. Keep acquisition-observation, geometric support, reference participation and model evaluation masks separately named.

## 3. Indexed-shard and HTTP invariants

The retained PHerc0009B ink level-2 metadata describes uint8 YX shape `[6340,5130]`, **outer shard** `[6656,5632]`, **inner chunks** `[512,512]`, one `sharding_indexed` codec, bytes→Blosc(zstd, typesize1, bitshuffle), and an end index encoded bytes(little-endian)→CRC32C. Thus the nominal index has `13×11=143` offset/length pairs and an encoded size of **2292 bytes** (`143×16+4`). Array-edge cropping must not shrink that nominal index or inner decoded chunk size. Independently validate other asset metadata; do not blindly reuse these constants.

The complete retained label-package inventory (`IsTruncated=false`, SHA256 `5a77abccd868ba5b87d16b14d7c1871a8d4c57d328074dc59327c6804d0734de`) lists whole level-2 shards of **17,784 ink + 7,830 supervision + 6,538 validation = 32,152 encoded bytes**. Prefer three separately bounded, inventory-ETag-pinned **whole-object HTTP200** reads if root later freezes acquisition. Then validate each full-object length/hash/index and decode only the planned inner chunks. This removes the need for a network range adapter for these assets; range-specific checks below apply only if a range path is actually selected. Do not confuse compressed object size with the much larger decoded canvas or automatically decode the whole canvas. The inventory contains no mapping-validity array, so its absence remains an explicit scientific-contract issue.

- Accept only the explicitly implemented schema/codec/key-layout subset. Validate ranks, positive dimensions, outer/inner divisibility, uint8, fill value, endian, codec sequence, storage-transformer absence and index location before calculating allocation/request sizes.
- Authenticate the index structurally with **CRC32C/Castagnoli**, not IEEE `zlib.crc32`. Verify its exact encoded/decoded lengths and reshape C-order little-endian uint64 pairs. The installed Zarr implementation confirms that its index shape is `chunks_per_shard + (2,)`; its CRC codec appends four checksum bytes. Bind that implementation/version and the runtime byte-order assumption used by a fixture encoder.
- Interpret offsets from the start of the shard. Convert uint64 fields to Python integers before arithmetic. Both values equal `2**64−1` denote an absent inner chunk; reject a half-sentinel, overflow-sized value, unsupported zero length, range inside the trailing index or past EOF. Validate the complete index, not only the selected entry. Reject overlapping payload intervals unless an explicitly supported format rule justifies exact aliases; do not require payloads to appear in coordinate order.
- Obtain and retain total shard length and a strong ETag/version from a valid index range response; require that same identity for payload requests. Abort on source change, missing validators or failed preconditions under the chosen snapshot policy. An ETag is an opaque version validator, not a SHA-256 checksum.
- Require HTTP206, exact `Content-Range` start/end/total, exact body length and identity transfer content encoding. Reject HTTP200 whole-object fallback, unsolicited multipart ranges, redirects outside the frozen policy, short/overlong responses, and changed totals/validators. Cap response streaming even when the server supplies misleading headers. Do not buffer an entire shard before noticing a cap violation.
- Freeze per-request, aggregate encoded-byte, decoded-byte, request-count, timeout and retry limits. Include index bytes, errors/retries and any range coalescing. Reject requests crossing index bounds or fetching unplanned chunks; no silent fallback to a full-shard download.
- Validate the Blosc frame's declared compressed length, uncompressed length and typesize before decoding. Require decoded length exactly `512×512` bytes for this contract, bounded output allocation and C-order reshape; trim only when assembling the logical array edge/ROI. A bounded encoded response alone does not prevent a decompression-size attack.
- Record raw index/payload SHA-256, object identity, requested/actual ranges, codec/runtime identity and decoded-byte hashes. Index CRC protects the index, not the compressed pixel payload. A locally measured SHA authenticates later reuse of those received bytes; it does not establish independent source truth or a complete-shard checksum.
- Treat valid absent-inner entries as the declared Zarr fill only under an explicit policy. A whole-shard absence needs an equally explicit, authenticated missing-key policy; generic404,403,412, transport, checksum and decode failures remain errors. A payload disappearing after a present index entry is a snapshot failure, not fill. Missing metadata is never a missing data chunk. Logical fill must still obey the participation rules above.

## 4. Synthetic fixture approach before live access

Use tiny independently encoded shards and a fake in-memory HTTP transport; no local HTTP server or public request is needed. Every fixture declares the expected logical pixels and exact request ranges before calling the reader.

| Fixture family | Required checks |
| --- | --- |
| Index and codec | Known CRC32C vector (`123456789` → `0xe3069283`), valid trailing index, corrupt CRC, truncated/extra index bytes, wrong endian/layout, unsupported codec chain, nondivisible shapes. |
| Offsets | Present entries out of coordinate order; valid all-absent entries; half-sentinel; Python-integer overflow boundary; past-EOF/index-overlap and cross-entry overlap. |
| HTTP snapshot | Correct206; ignored Range200; incorrect start/end/total; short/overlong body; changed/weak/missing ETag;412; generic404; explicit missing-key policy; nonidentity encoding. Assert failure occurs without consuming an oversized body. |
| Decode bounds | Correct Blosc frame; wrong cbytes/nbytes/typesize; corrupt compressed stream; header claiming enormous output; decoder output length mismatch. Assert rejection before oversized allocation. |
| ROI geometry | Asymmetric numbered pixels, nonzero shard coordinates, inner boundaries, four-inner-chunk ROI, final partial array edge and out-of-bounds crop. Distinguish XY/YX and C/Fortran ordering. |
| Transform/depth | Distinct coordinate landmarks; a nonzero signed offset applied exactly once at the specified level; already-applied offset; fractional mapping with explicit resampling; normal reversal exactly once; known physical depth positions and pooling centers. Never make the fixture derive expected positions from the reader's own formula. |
| Mask semantics | Identical zero labels with known-negative, unsupervised, validation, unmapped, seam and measured states. Verify only the predeclared domain participates, missing/unknown cannot become background, and categorical transforms preserve allowed values. |

A fixture can establish mechanical correctness for a declared contract. It cannot supply missing registration, annotation-depth or historical-exposure evidence. Keep decoder readiness separate from scientific acquisition readiness.
