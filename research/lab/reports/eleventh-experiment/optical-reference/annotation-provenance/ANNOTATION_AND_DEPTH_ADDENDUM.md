# Primary-source closure of Frag4 annotation and depth conventions

**The published EduceLab-Scrolls protocol supports a conditional supplied-reference comparison on Frag4: its exposed-face labels were made from registered 1000 nm infrared photographs, zero/nonzero labels are used as negative/positive classes inside surface support, and its 65-channel rendering convention places the segmented surface at index 32 with one-voxel normal steps.** These are publication/source-supported conventions, rather than conclusions from the number of layers. ## Optical labels and mask participation

[Section 2](https://arxiv.org/html/2304.02084v4#S2.p1) explicitly names PHercParis1Fr39 among the four fragment surfaces. [Section 2.1](https://arxiv.org/html/2304.02084v4#S2.SS1.p2) identifies the ground-truth photographs as 1000 nm infrared images acquired by Brigham Young University beginning in 1999; the following paragraph says the binary ink images are created by labeling those photographs. This is specific support for the published four-fragment dataset, beyond the later tutorial's illustrative Paris2Fr47 example. The same section's eight-fold top/bottom split describes the **paper's** historical benchmark, not a clean holdout from today's initialized models.

[A.8](https://arxiv.org/html/2304.02084v4#A1.SS8.p1) fixes the CT texture/UV image and moves the infrared image with a deformable warp. Paragraph3 states: “Instead, we align these images manually by identifying visual feature points that are common to both images.” It specifies Photoshop Puppet Warp. Paragraph4 acknowledges time cost and human error; it supplies no numerical per-fragment registration residual.

[A.9 paragraph1](https://arxiv.org/html/2304.02084v4#A1.SS9.p1) states: “For binary ink classification, an additional step is included, where a binary segmentation mask is created by tracing the ink regions.” It continues: “This is performed manually using the Quick Selection tool in Photoshop, under the supervision of a papyrologist to help disambiguate difficult spots based on papyrological context.” Paragraph2 acknowledges binary-label error. The publication establishes an optical/manual protocol; the exact identity of the operator and a hash bridging every retained PNG to the publication are not supplied by these paragraphs.

[A.5 / Figure11](https://arxiv.org/html/2304.02084v4#A1.F11) calls the mask a **binary mask indicating surface bounds**. It is not a modern S/V confidence mask. The paper's declared binary classification protocol treats the traced image's remaining supported background as no ink; this now has direct implementation evidence.

## Published physical/depth convention and its limits

[A.5](https://arxiv.org/html/2304.02084v4#A1.SS5.p1) describes a six-channel PPM with XYZ position and normal XYZ. Paragraph2 derives position and **normalized** normal by barycentric interpolation. This closes the published representation; the exact large retained PPM's binary header, frame and matching native CT revision still require direct evidence if used.

[A.6 / Algorithm3](https://arxiv.org/html/2304.02084v4#alg3) uses trilinear interpolation at `p+zδn`, writes to `S[z+r,y,x]`, and iterates `z∈[-r,r]`. [Paragraph7](https://arxiv.org/html/2304.02084v4#A1.SS6.p7) explicitly sets **r=32 and δ=1 for the surface volumes in this work**, yielding 65 channels and preserving original image resolution. For the declared published convention, file index `k` therefore corresponds to `p+(k−32)n`, and index 32 is the segmented surface. The discovered Frag4 metadata (65 layers, 3.24 voxel size, vc_layers description) and linked published dataset are consistent with that protocol. This supports proceeding conditionally with index 32; it does not authenticate the binary/argv of the specific stack or prove its normals match the modern 9 µm model. Nominal offsets are `(k−32)×3.24 µm` if the published unit-voxel sampling applies to this exact source; state that assumption and test the physical rendering separately when needed.

**Keep the two PPM names distinct.** The discovered region descriptor links the rendered TIFF surface volume to `*_surface_volume.ppm`; the pinned loader reads PPM positions to index the *declared volume*. It should not automatically be treated as a native-source CT map. The separately listed `PHercParis1Fr39_54keV.ppm` is the original native-map candidate. Header/frame verification must choose the map matching the intended volume. A.6 explains that direct rendered-image learning can discard the original PPM, so a bounded rendered-surface comparison need not reconstruct native mapping first if it uses the declared publication convention and states its limits.

No published **uint16→uint8 CT mapping** was identified. The pinned `dataset.py` lines283–289 calls `uint16_to_float32_normalized_0_1`, converts to Torch, applies random horizontal/vertical flips and `Normalize((0.5,),(0.5,))`. The called utility's body was not fetched, so its exact arithmetic is not claimed here. The uint8 operations elsewhere in this file concern RGB labels and output images. A.1.1 mentions manual intensity windows for 16-bit reconstructed TIFFs in the 2009 acquisition subsection; that is not evidence for Frag4's 2019 reconstruction window or a later eight-bit conversion. A right shift/division followed by uint8 casting, factor-three pooling and robust 9 µm normalization would be **our explicitly frozen model adaptation**, not reproduction of the historical ink-ID input.
