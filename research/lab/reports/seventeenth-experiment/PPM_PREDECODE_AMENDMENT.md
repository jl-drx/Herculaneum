# Conditional PPM serialization check, frozen before sparse acquisition/decode

2026-10-08 UTC. The fetched, Git-blob-verified historical ink-ID reader/writer uses native-host struct double packing, with no portable endianness field. This source finding motivates an explicit amendment to the initial conservative source-only byte-order gate. No scientific PPM binary sample has been interpreted, and no label/model result informed these rules. Independent technical review accepted the distinction between conditional decoding and historical provenance.

The unchanged sparse schedule may collect opaque bytes after the header establishes ordered6-component double records, body offset and exact canvas/body extent. Numeric interpretation will test exactly two candidates: little-endian float64 and big-endian float64. No other layout, byte order, tolerance or schedule will be tried.

For each result.ppm object, test ALL sampled records from both cases and all3x3 neighborhoods, not just their centers. An exact all-six-zero tuple is an invalid sentinel and is counted/reported. Every other tuple must have finite XYZ and normal components, with absolute(norm(normal)-1)<=1e-5; at least one nonzero tuple is required. This tests the publication's normalized-normal invariant. Nonfinite or nonunit records reject that candidate; failure is an invariant mismatch, not proof of the historical file's byte order.

For each surface_volume.ppm object, test ALL sampled records against their independently scheduled native x,y coordinates. Require exact(x,y,32,0,0,s), with s either+1or-1 and constant across every sampled record for that object. No zero sentinel is allowed for this flat-map test. This is the current renderer's documented output hypothesis, whose exact historical invocation remains unverified. Failure rejects this hypothesis; it does not establish the file is corrupt.

Exactly one passing candidate per object allows downstream geometry only under that explicitly recorded, invariant-consistent serialization interpretation. Both or neither passing means unresolved serialization: retain both candidate validation summaries and opaque bytes, and omit that object's numerical geometry. Do not widen tolerances, sample different locations or choose based on IR/labels/scores. No assumption that the two map variants have the same byte order. No claim that this authenticates the producer's hardware, native CT frame, anatomical normal direction, historical rendering parameters or regional optical warp.

This amendment supersedes only the initial design's requirement to resolve endianness from source text before sparse acquisition/numeric interpretation. All network/resource limits, image and CT analyses, fixed cases and no-optimization rules remain unchanged. Acquisition plans and numerical helpers must pin this file with the original design and pre-execution clarifications.
