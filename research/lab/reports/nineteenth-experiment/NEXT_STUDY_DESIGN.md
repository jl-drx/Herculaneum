# Next Plinius study: matched depth-fusion adaptation

The immediate research question is whether the same explicit-depth feature bundle becomes useful when it can alter the frozen U-Net's representation, rather than only its final logits. Phase 18 did not answer that question: its 801-parameter output branch mostly reduced prediction drift and missed the improvement screen. This proposal is a separate experiment, with no training results yet.

Use the original strict seed42 state, not either phase 18 adapter. Both arms add a 5,296-parameter residual to the 32-channel output of `depth_fusion`, before the unchanged 2D U-Net. Each branch is Conv3d(3→8, kernel 3) → LeakyReLU(0.01) → concatenated depth mean/max → Conv2d(16→32, kernel 3). Both projection weights and biases start at zero. The original depth stem and entire 2D U-Net remain frozen and in evaluation mode. Gradients must traverse the U-Net to its input; computing its output under `no_grad` would prevent adapter learning.

The raw control sees clamped previous/center/next planes. The candidate sees the center plane, centered axial differences with full one-sided endpoints, and `(j−8)/8`. These are the same feature definitions as phase 18. The coordinate denotes a nominal stack index, not authenticated physical ink depth. The control can itself derive differences; the comparison tests the explicit feature bundle under this architecture. Against phase 18, both insertion point and output capacity change, so a cross-phase gain would not isolate either cause. Candidate versus raw control is the primary comparison.

The finite synthetic integration test in this phase establishes only mechanics. Its Gaussian input, spatial MSE target and one SGD update per arm must never be reused as a trained research adapter or interpreted as evidence of ink detection.

## Concrete developmental protocol to implement

- Preserve the exact phase 18 PHerc0139 manual support, normalized 17-plane inputs, D4 augmentation and 32 scheduled batch-two updates. Keep retired validation and pseudo targets out of the manual objective. Historical pseudo arrays may verify old schedule fingerprints only.
- Give both arms exactly equal initial tensors from seed 20261008 and identical optimizer schedules. Retain the phase 18 manual smoothed BCE plus unit-weight seed42 preservation KL on manual support, with the same averaging convention. Use AdamW with learning rate 0.001, betas (0.9, 0.999), epsilon 1e-8, zero weight decay and gradient clipping at norm 1. No learning-rate sweep is part of this proposal.
- Before any update, verify the new insertion reproduces original seed42 outputs on every scheduled input and that retained teacher logits bind to those exact inputs. Cache original fused features only with source/input/state/mode/dtype identities. Include only the new 5,296 parameters in the optimizer. Preserve and check all original parameters, buffers and module modes.
- Retain loss/gradient/optimizer traces and fixed full-schedule risks at updates 1, 8, 16 and 32. Evaluate final states only. Independent checks must verify loss derivatives, clipping, updates, input identities and state immutability; the synthetic smoke is insufficient for this scientific execution.
- Report both final arms on all six fixed Paris1/Paris2 contexts, using the original literal cutoff 0.7558947205543518 and unchanged tile normalization, sigmoid and Hann blending. All are reused development evidence. Keep every context, including the weak ones, and compare against the unchanged baseline as well as the raw control.
- Preserve the phase 18 practical screen for comparability: each candidate base/full training improvement ≥1e-4, candidate full-risk advantage over raw ≥1e-4, Paris2 macro AUROC and AP advantages over raw each ≥0.005, and no per-context AUROC/AP loss versus baseline exceeding 0.02. These margins do not imply statistical significance or independent confirmation, and passing them does not automatically authorize GPU scaling.
- A bounded CPU implementation is the next execution target. Freeze exact source/input/output hashes, numeric tolerances and enforceable runtime/memory/storage budgets in the executable plan after its code exists. Do not estimate a full scientific training runtime from the synthetic smoke alone.

This is a concrete design, not a claim that its scientific runner or all execution gates already exist. Phase 19 executes only source audits and mechanics checks. A new scientific runner and its pre-execution technical review remain necessary.
