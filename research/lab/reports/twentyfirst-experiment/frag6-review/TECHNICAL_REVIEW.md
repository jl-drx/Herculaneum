# Frag6 Stage A technical review

The final frozen implementation is technically ready for root-authorized Stage A acquisition. No unresolved source issue blocks that bounded execution. `TECHNICAL_GO.json` binds the exact executable plan, all eight sources, author fixtures and independent review receipts. It is a technical finding, not the separate live-request GO required by the controller and worker. Stages B/C, numerical geometry, labels, models and paid resources remain outside this review.

The implementation accepts only the four retained HTTPS objects and exact pinned validators/totals. Each request reserves its useful length plus one excess byte and one attempt in an atomically replaced ledger, with file and directory fsync before opening. A failed attempt retains its reservation. All emitted request headers include exact Range, If-Match and identity encoding. HTTP 206, Content-Range, Content-Length, strong ETag and MIME are checked before a body read. Duplicate singleton identity/framing headers, transfer encoding, unexpected encoding, redirects, errors and whole-object responses stop. There is no retry, alternate URL, whole-file fallback or subsequent-stage reader.

Each request has a 60-second absolute timer spanning connection, headers and reads, separate from the 20-second connection/socket timeout. Sequential bounded reads preserve partial bytes returned to the reader and an explicit excess-byte sentinel. Successful and partial files are hashed. This does not count total wire traffic or recover bytes held privately by a failing HTTP library call. No process-crash or lost-success-response behavior was tested.

The PPM parser interprets only the exact UTF-8 header through the LF-delimited terminator. It validates positive dimensions at least 11, all six required unique fields, ordered six-double records, versions 1/1.0 and the exact object extent. Comments and header text remain literal; the rest of the 1,024-byte prefix stays uninterpreted. It neither decodes numerical records nor chooses byte order or source volume.

Each classic TIFF declares its own II/MM order. The reader validates the header pointer, bounded IFD count/table, unchanged count, no subsequent IFD, unique tags, type/count conventions, metadata spans and object bounds. It requires dimensions matching the PPM and one uncompressed unsigned 16-bit grayscale strip with supported orientation/fill order/planar/sample-format/predictor conventions. The strip has exactly width × height × 2 bytes, covers the canvas and overlaps no structural metadata. External metadata spans overlap neither the header, IFD, strip nor each other. Only bounded ASCII ImageDescription can trigger another read; absent and inline descriptions are explicit. Text remains a publisher declaration, not authenticated render execution.

The review found and resolved three pre-execution parser details: fixed convention tags must use SHORT instead of universally accepting LONG; Compression=1, SamplesPerPixel=1 and RowsPerStrip=4294967295 defaults must be applied and recorded; both established PPM version declarations 1 and 1.0 should be supported. The author additionally changed header splitting to literal LF and made final resource failures persist STOP. These corrections occurred before source freezing or live requests; prior fixture source snapshots are preserved.

Independent verification on the final relevant sources passed:

- 72 parser assertions, including independent TIFF byte orders, defaults, tag types, bounds/overlaps, description handling and malformed PPM cases. A Unicode line-separator inside a comment confirms literal-LF parsing.
- 307 transport assertions across 40 fake scenarios, including reservation before opening, exact request headers, rejection before body reads, failed/partial/excess transfer accounting, no retries, and absolute open/read deadlines.
- A separate complete synthetic Stage A traversal using maximum 128-entry IFDs and 65,536-byte descriptions: exactly 13 requests, 202,301 reserved response-body bytes and 202,288 returned synthetic bytes. The first four request order, all three TIFF declarations, unresolved render fields and no stage advance were checked.

The first independent transport fixture stopped because its reviewer assertion incorrectly expected an unreturned fake response to be closed when the opener timed out. That source, STOP receipt and fake ledgers are retained. Version 2 corrects only that expectation; the source transport and budget contract were unchanged. No producer failure or live retry occurred. The author separately retained a final passing 102-check fixture suite bound to all eight final sources.

The worker applies the 1 GiB address-space limit and measured 256 MiB RSS/32 MiB artifact checks. A separate controller polls worker RSS, output bytes and the 1,800-second wall limit every 0.1 seconds and kills the process group on breach. It records an independent terminal result if the worker fails. Polling and measured acceptance are not instantaneous kernel RSS/disk quotas. Payload bounds are substantially smaller than those resource ceilings.

No live request, actual scientific-array read, numerical PPM/image decode, model call, credential action or paid-resource operation occurred in this review. Actual source availability, validators and storage structure remain untested until root runs the frozen plan. A successful acquisition establishes storage structure and literal declarations only; any unsupported layout, changed identity, malformed response or exceeded limit must remain a STOP without fallback.
