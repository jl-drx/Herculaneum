## Evidence that changes our next step

The [fifth experiment](../fifth-experiment/RESULTS.md) verifies source-to-render correspondence at ten points and reproduces the previous central predictions bit for bit within a larger context. It still yields no defensible letter sequence. It is a post hoc diagnostic, not an accuracy benchmark. Stop expanding the crop simply to follow stronger model responses.

Our PHerc1667 reference overlaps the baseline training corpus and may include pseudo-label supervision. It remains useful for detecting pipeline mistakes, but cannot establish generalization. Two seeds sharing training data are not independent replications; overlapping depth windows are not separate biological samples. Source agreement proves which voxels were sampled, not that the mesh follows the correct written surface.

## Next study: contract and evaluation benchmark

1. **Resolve candidate contracts before downloading weights.** Pin the repository and model revision, license, tensor names/shapes, input depth, pooling, normalization, orientation and output semantics. Inspect known checkpoint repairs explicitly. Define byte, disk and CPU bounds before retrieval. Stop on an unresolved architecture mismatch or missing essential configuration; do not force partial state loading.
2. **Build a supervision and physical-overlap ledger.** Every region must identify scroll, scan energy/resolution, volume, surface revision, native coordinate support, annotation version, supervision mask and teacher provenance. Keep real annotations, uncertain regions and pseudo-labels separate. Unsupplied labels are not negatives. Inventory all teacher/student training sources as well as the proposed evaluation source.
3. **Freeze three distinct uses of data.** Retain the existing training-overlapped reference as a pipeline check. Establish annotated validation regions with physical sampling support disjoint from known training/adaptation support where possible. Keep unopened target regions for descriptive transfer evaluation. If public training lineage is incomplete, label generalization status unresolved rather than calling the benchmark held out.
4. **Compare fixed recipes on identical support.** Begin with the existing baseline and one newer, fully verified checkpoint; add ensembles only after the constituent models are understood. Use the same source bytes, geometry and observation masks, physical units and admissible evaluation domain. Predeclare any depth averaging and weighting. Do not choose the model by resemblance to an expected letter on the target.
5. **Use metrics that match the available truth.** On authentic, independently supported annotation, report precision–recall behaviour and performance at a threshold fixed using development data, stratified by physical region. Bootstrap physical regions, not correlated pixels; with too few regions report descriptive results instead of misleading confidence intervals. Against teacher labels, report teacher agreement separately. For target transfer without ground truth, report coverage, source-supported structure, controls and uncertainty without an accuracy claim.
6. **Decide using a frozen acceptance criterion.** Before evaluation predictions, record the minimum worthwhile improvement and any non-inferiority margin, number of physically distinct regions, compute limits and stopping conditions. A numerical accuracy gate is deliberately not invented before annotation reliability and baseline variation are measured. Retain every arm and failure; add a new protocol version for changes instead of editing a frozen run.

The immediate next work is candidate-contract verification and the evaluation ledger. Start with Russo's recommended dense/control pair because it advertises the existing released inference contract; strict state loading must still confirm that claim. Include exact existing baseline checkpoint IDs, and consider a predeclared earlier released checkpoint as a baseline-selection control rather than declaring a new method superior to one arbitrary final checkpoint. Nieuwlaar follows after its architecture contract is resolved. The rules/training audit identifies PHerc1667/w029 as a candidate for a small corrected-mask comparison, subject to aligned-source and depth mapping verification. A withheld mask inside a trained segment is not segment-held-out validation; unresolved teacher or physical overlap must remain explicit. These checks can proceed on CPU without Runpod. No newer weights, training corpus or GPU job were acquired as part of this source audit.

## Geometry track: a separate hypothesis

If native CT review establishes wrong-layer sampling, sheet switching, flattening distortion or inadequate written-surface coverage, choose the smallest relevant geometry test. Stevens' connectivity method can be exercised with two overlapping retained geometry patches plus a clearly synthetic displaced patch, with a fixed rejection rule and strict CPU limits. This would test a bridge and injected-conflict behaviour, not authenticate a real wrap. ScrollFiesta or Socratic reproduction would then require a separately bounded native-CT/surface-prediction dataset and geometry ground truth.

Report observed source support, normal degeneracy, incorrect sheet connections, compatible-patch rejection, overlap, unique physical coverage, distortion, memory and wall time. Optimize measured geometry quality rather than the apparent attractiveness of an ink output. Do not run a whole-scroll reconstruction merely because software is available.

## GPU pilot and experiment discipline

The £10 allowance is a **total first-pilot cap**, including failures, retries and attributable storage, transfer, tax and currency margin. Choose hardware from measured memory needs and current all-in price; an H100 is not automatically the economical choice. The first paid run should validate the pinned CUDA environment, strict loading, reproducible inference, throughput, memory, checkpoint/result persistence and shutdown on a frozen small workload. A short pilot cannot be represented as reproducing an author's multi-hour training result.

Before launch: freeze the workload and container digest; verify worker delivery of scoped temporary credentials; quote current price and a conservative runtime budget; verify an independent shutdown mechanism that does not rely on the GPU process remaining healthy. Aggregate spend across attempts. Do not silently restart a failed paid job. Runpod secret import and worker delivery are still unverified, so paid launch is not ready. No paid resource was created in this work.

For every experiment retain the hypothesis, selection timing, immutable code/config/environment pins, source and supervision provenance, physical split audit, resource cap, raw outputs, masks, metrics and conclusion. The [experiment register](experiment-register.json) links the five completed reports and their limitations; it is a current inventory, not a retroactive preregistration. Keep an append-only lineage between revisions. Assign one execution owner after the freeze; reviewers write additive reports, never edit executing code. The fifth experiment's original integrity stop and separate recovery remain visible.

## Prize and publication handling

Use the exact current official rules and per-asset terms in [RULES_AND_TRAINING.md](RULES_AND_TRAINING.md). Target eligibility is distinct from satisfying an award's evidence and submission conditions. Code licenses do not relicense scans, labels or model artifacts. Keep novel text discoveries private while preparing the required verifiable evidence; distinguish diplomatic readings from restoration, language-model suggestions and translation. Assistant agreement does not replace specialist papyrology.

First Letters is the nearer discovery goal; a Progress Prize would require a measurable, reproducible contribution beyond using existing software. Grand Prize remains a longer-term option, not a promise made by this setup. Choose a prize track before freezing a submission pipeline. First Letters requires ten legible letters in one 4 cm² area, source-traceable static images and meshes, no training/prediction overlap, false-positive controls and public known-ground-truth validation. It permits human-in-the-loop work; its own section does not impose the Grand Prize's eight-hour cap. Grand Prize requires an automated unrolling pipeline with at most eight documented hours of human input, while separately allowing unlimited generic ML dataset creation. Prior unmeasured intervention is unknown, not zero. Record actual interventions and their purpose prospectively in [the intervention ledger](intervention-ledger.json), with uncertain classification flagged for organizer clarification before any submission. Grand Prize also has target high-resolution restrictions, training/prediction non-overlap and additional tracking/release requirements; a teacher's provenance is therefore part of eligibility, not merely model quality.

General award terms require releasing the method under a permissive license to accept a prize; Grand Prize explicitly requires public GitHub code. Stevens' GPL code and restricted dependencies in the full ScrollFiesta stack need a concrete license-compatible packaging or replacement review before we promise a compliant submission. Our MIT adapter does not relicense a combined method. Private evaluation can inform our work without treating every inspected component as an adopted submission dependency.

Before an eventual submission, refresh the live rules, check the exact scroll/volume and track, prepare the required reproducible package and verify the permitted human intervention and publication conditions. No submission, disclosure or external contact is authorized by this audit alone. No credible prize claim currently exists.

GitHub remains appropriate for reusable code and non-sensitive configuration. R2 is the intended private store for large results and checkpoints. These new private experiment and audit records are currently local to the cloud workspace; they have not been uploaded to R2. Saving startup guidance is not proof of a completed backup or future restoration.
