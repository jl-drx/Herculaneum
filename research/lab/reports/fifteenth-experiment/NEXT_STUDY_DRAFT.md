## Resolve the CT reader before prediction

The prior Frag4 reader used two full-width TIFF row bands per plane. Its retained ledger shows 1,425,096,672 response bytes across 255 successful requests for two selected contexts over 51 planes; only 270,729,216 bytes were selected crop pixels. Reusing that layout for Frag1–3 would require about 4.6 GiB for six regions, conditional on the new TIFFs having the same layout. Frag2's full-width 1152-row band alone would exceed the previous per-response cap. These are calculations from retained metadata, not observations of the new TIFF byte layout.

First freeze a small header/IFD-only audit for the exact source objects and selected boxes. Resolve classic/BigTIFF, byte order, dimensions, sample type, compression, strip/tile layout, length and stable HTTP object identity before any pixel acquisition. Keep verified TLS, bounded attempts and body bytes, exact HTTP 206/Content-Range checks, identity encoding, strong validators and hashes. No redirected source, decompression expansion or fallback full-object download. If selected TIFFs lack stable validators or a supported layout, record that failure and revise the reader plan explicitly before more requests.

Choose the lowest practical combination of transferred bytes, requests and retained storage after that audit. A full-width band reader is simple but wasteful; per-row ranges save bytes but require many requests. Multipart ranges are a possible optimization only if an explicitly bounded probe establishes actual support and a tested parser checks every requested span. An alternate chunked source needs a source/coordinate identity bridge; similar dimensions alone are insufficient. Freeze the chosen strategy and worst-case byte/request/storage budget before obtaining pixel payloads. A diagnostic efficiency experiment is useful even if it rejects multipart serving.

Retain the intended adapter without tuning it from results: source planes 7:58 (51 planes), fixed factor 3 averaging in XYZ to 17×384×384 float32 at nominal 9.72µm. The exact implementation, binary layout and all object identities still need a future input contract. Acquire and verify all inputs before scientific model execution. Do not reuse the earlier oversized-band cap silently or infer true sampling resolution from metadata alone.
