# Native model input and historical factory contract

**The native checkpoint's documented input is the same 17-plane hybrid model family as seed42, but its native default selects planes 6–22 from a 28-plane volume.** It does not consume all 28 planes or apply the aligned-input pooling recipe automatically. The four advertised native depth intervals resolve to four different 17-plane crops. All claims below come from retained metadata or the exact historical source; this audit has read no checkpoint values, CT arrays, label arrays or model predictions and has constructed no model.

The historical source is Villa `3ea17f54a9b3d5fd1aaf73e1d2c8386dbaa9f30e`, as named by Nieuwlaar's retained `training/REPRODUCE.md`. The authored config and scripts are pinned at Nieuwlaar GitHub `217e7521670db49cde97872ea6a8bdfb80c449f1`; the advertised safetensors is HF revision `b894a0493ab2291cc8dc3247020c0d7cb0967a58`, path `weights/dense_native_016000.safetensors`, 272,767,904 bytes, SHA256 `d3d95dc41dcb24ed76b84b5e12ca5dae25d7fb34edf1dfbb93e0186f91e6fc6d`. The current focused seed42 factory is Villa `e0bbb8b40a2db58b1d71864f286eb85717e59e64`. These revisions must stay distinct.

The source pass used 16 HTTPS attempts and 295,999 observed response-body bytes over 87.798 seconds. Fifteen requests returned text/JSON; a preserved 404 showed that the guessed historical `data/dataset.py` path did not exist. An exact-commit directory lookup located `data/ink_dataset.py`; it was a different counted lookup. No URL was retried. Request scheduling, TLS/identity encoding, exact URL restrictions, byte counts and SHA256s are retained in `source/request-ledger.json`. Response bodies were bounded to less than 1 MiB each; overall reservations, attempt and absolute timers stayed within root's limits. A separate root-authorized one-request stage then fetched the exact historical activations module: 4,158 bytes in 0.693 seconds, Git blob `08210f4b3d1c6dd3d3fc87e8c81bd68e193846ce` verified. Across both stages: 17 attempts / 300,157 observed body bytes. This accounting covers observed response bodies, not TLS framing or unread socket buffers.

## Construction and aliases

The authored architecture keys exactly match retained seed42: `mode=flat`, `model_type=vesuvius_unet_3d_stem_2d`, one image channel, `patch_size=[17,128,128]`, autoconfiguration, BasicBlockD encoder, ConvBlock decoder, 16 stem channels, and a single unactivated ink output with no depth projection. Historical `infer.py:138` copies the authored dict and sets both `crop_size` and `patch_size`; old `make_model.py:124` directly constructs this family. No old `InkConfig` class is needed.

The stem has two 3×3×3 convolutions with affine InstanceNorm3d and LeakyReLU. A 1×1×1 attention head produces a FP32 depth softmax; a weighted depth sum and depth maximum are concatenated into 32 features. The 2D body uses [128,128], spacing [1,1], autoconfigured residual encoder and shared features-only ConvBlock decoder plus one ink head. The fixed depth check remains 17. The historical and current stem equations agree by inspected source; renamed variables, docstrings and an unused `output_channels` property differ.

Historical `NetworkFromConfig` has changed considerably by the newer vendor revision. The exact old encoder and decoder are retained for an actual parity comparison. Source differences in the encoder add optional feature gates and fix the nonresidual externally pooled path; neither is selected by this BasicBlockD/conv configuration. Decoder additions support modified skip widths and optional upsampling modes; the selected default widths and transposed-convolution equations match the old source. The old and current `resblocks.py`, `simple_conv_blocks.py`, and `utilities/utils.py` have identical Git blob IDs; this audit also rehashed the retained bytes as Git blobs before treating them as reusable. This is an active-path source trace, **not an executed numerical parity result**.

Phase21 independently established 508 F32 names, 244 expected duplicate-name pairs and 20 singleton groups. Conditional on pairwise byte equality, this is 264 distinct factory groups / 34,546,498 parameters. The 68,175,426 named element count includes duplicated names. Safetensors stores each name separately: shape equality is insufficient. Every pair must compare byte-for-byte before strict load; preserve all 508 keys rather than relying on last-write wins. Preserve the complete missing/unexpected key report and compare loaded state back to each input value. Never repair a conflict by dropping an alias.

The historical convenience loader is unsuitable as a qualification mechanism: `infer.py:1103` uses unrestricted `torch.load(..., weights_only=False)` and `infer.py:1343` loads with `strict=False`. Our qualification must use the bounded safetensors path, check the whole-file hash, finite values and aliases first, then `strict=True`. The historical recipe's reconstructed `step=16000` is a user-supplied wrapper field, not embedded provenance in the bare safetensors.

## Exact depth and patch semantics

`old-infer.body:360` centers an interval by `start = n//2 - 17//2`; `:1655` applies this after resolving/clamping half-open CLI bounds and reverses only afterward if explicitly requested. For even source depth, this selects the upper central plane. A 17-plane model input does not imply 17 source planes from the start of the source volume.

| Source / command | Actual half-open selected planes | Model calls per spatial tile |
|---|---|---:|
| 28-plane native, default | `[6:23)` | 1 |
| 21-plane aligned, default | `[2:19)` | 1 |
| native `0:20` | `[2:19)` | 1 |
| native `3:23` | `[5:22)` | 1 |
| native `5:25` | `[7:24)` | 1 |
| native `8:27` | `[9:26)` | 1 |
| aligned `i:i+17`, i=0…4 | unchanged five 17-plane intervals | 5 across ensemble |

The dense-native headline and post-strip recheck use one default window, forward direction, 0.5 overlap, Hann blending and no compile. The separate soup/native ensemble example uses four windows on title and three on w024; the aligned ensemble uses five. These are different recipes, not a hidden part of the trained checkpoint.

The historical reader (`:730–843`) uses resolution `0` by default, infers Z-first layout from `argmin(shape)==0`, and for robust preprocessing casts directly to FP32 without uint16-to-uint8 rescaling or intensity clipping to 200. Requested depths shorter than 17 receive zero padding before `(17-n)//2` and the remaining zeros after; the complete padded crop is normalized. Spatial samples outside the image also receive zeros before normalization. Normal full 128×128 edge-aligned tiles need no spatial padding; small images do. Our future input protocol should reject unexpected axes/depth/geometry explicitly rather than silently trusting this axis heuristic.

The current reference's complete 128-pixel grid at stride64 agrees with historical `_sliding_positions_1d` for sizes ≥128: include the last edge-aligned tile. Historical full-frame inference also uses low-resolution nonzero occupancy to avoid empty tiles (prefer pyramid level3, with fallback) and checks the selected raw patch's nonemptiness before normalization. These occupancy tests are computation shortcuts, not anatomical validity or an ink mask. They differ from our deliberately complete bounded region evaluation and must not be silently borrowed.

## Normalization, training and output differences

For inference, `OmeZarrBlockDataset.__getitem__` takes the padded H×W×Z FP32 crop, moves Z first and calls `normalize_robust` on the whole crop. It uses no supervision, geometry or nonzero mask. Clip at the linear 1st/99th percentiles, subtract the post-clip median, and divide by 1.4826×MAD. A scale below 1e-6 or nonfinite falls back to preclip standard deviation, half the percentile span, then 1.0; final nonfinite results become zero. The source function otherwise matches the retained vendor byte-for-byte except `_prepare_image`: old float32 inputs may alias and mutate, while the current version always copies. A parity test must provide independent input copies and preserve the historical HWC→ZYX memory layout as an explicit case.

Training differs at the boundary. `old-ink-dataset.body:1953–2000` rejects out-of-range Z when jitter is enabled, reads a padded crop, and normalizes only `image_valid_slices`, leaving padded spatial voxels at zero. Inference normalizes the entire padded crop. Training applies later augmentation after normalization. The authored jitter is 17 planes with random integer offsets −2…+2, probability1, no Z padding, disabled for validation and when augmentation is off (`:91–147`). Seed42's retained config adds `training_only:true`; the old function does not consult that key and explicitly checks `do_augmentations` / `is_validation`. Do not claim every authored config field is byte-identical.

The training loss config also matches seed42: BCE smoothing0.5 (hard class targets .25/.75), dice smoothing0. The new model is an authored continuation from Russo's dense ex016 checkpoint, with dense native PHerc0139 representations added to the prior corpus. These are declared recipe facts, not verified execution provenance. The teacher-derived benchmark classes remain correlated with its 78keV teacher family; source validation cannot turn them into independent human labels.

Historical `infer.py:650` converts logits to FP32 sigmoid probabilities before blending. It only bilinearly resizes if output spatial dimensions differ; the configured same-size hybrid has no expected resize. Nonperiodic FP32 Hann weights are normalized by their maximum and floored at .001 (`:297`). Tiles contribute weighted probabilities and weights in FP32; divide where weight >1e-6, clip to [0,1], multiply by255 and truncate to uint8 (`:1551`). The author's `zavg_infer.sh` and `native_bench.py` then decode `clip((uint8-64)/128,0,1)`. The ensemble is the arithmetic mean of these decoded, quantized maps.

Our seed42 studies retain raw FP32 sigmoid probabilities before display scaling. That differs from the author's benchmark path: clipping and uint8 quantization create ties and can change AUC/AP; averaging stretched/clipped maps need not preserve rankings from averaging raw probabilities. Do not compare thresholds, ensemble maps or reproduced scores across these representations without an explicit output contract. The author's decode is a documented score transform, not independent probability calibration.

The historical training/reproduction environment used Torch2.4.1+CUDA12.1 and NumPy2.2.6. The config's `mixed_precision=fp16` governs CUDA autocast; historical CPU inference uses no autocast. A fixed Torch2.12 CPU comparison can establish implementation agreement under this runtime, not reproduce historical GPU rounding or published accuracy.
