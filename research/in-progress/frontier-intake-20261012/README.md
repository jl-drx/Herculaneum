# First execution of the broader Plinius programme

12 October 2026. Implements the approved [active plan](../../CURRENT_PLAN.md)
alongside the unchanged native0139 CPU study. This is a completed preparation
and geometry-reference batch, not a trained frontier model or a GPU launch.

## Concrete results

**Surface identity deserves its own endpoint.** The first lexicographically
adjacent pair in the public harmonized instance dataset contains 18 labelled
sheets and 13,622,610 labelled voxels. Ordinary 6- and 26-connected components
of the *exact reference foreground* both produce six components, including a
mixed component. The minority-sheet membership is 84.45% of reference voxels
under the declared majority-identity metric, despite perfect binary foreground
agreement. Thus binary agreement plus component extraction is insufficient for
this reference. It is not a measured failure of m7, F0, recto prediction or a
released tracer, nor proof of our new method's superiority. These are thick
sheet-instance labels; thin recto targets solve a related but different task.

A separately declared follow-up checked the simpler explanation that joining
files caused all the mixing. Different arithmetic reproduced the primary metric;
mixing persists within each cube, and remains 73.61% with cross-file connectivity
disabled. The [boundary control](geometry/BOUNDARY_CONTROL.json) supports the
limited reference-identity conclusion without promoting it to native accuracy.

See [reference results](geometry/reference-analysis/RESULTS.json) and the
[fixed reference panels](geometry/reference-analysis/REFERENCE_PANELS.png).
Seven metric fixtures cover identity, arbitrary IDs, merges with unchanged
foreground, splits, missing sheets, unknown exterior and empty references.
Zero-labelled voxels are not silently treated as physical negatives.

**The native geometry intake is real and bounded.** All 324 frozen CT requests
completed: 679,477,248 bytes (648 MiB), with exact lengths and hashes. They assemble
12 contexts of 192³ uint8 voxels, six each from PHerc0800 and PHerc0814, totalling
81 MiB plus array headers. Every voxel is backed by a retrieved chunk; 72 direct
coordinate spot checks agree. All 36 prescribed central CT planes were inspected
with fixed 0–255 display. No native surface-prediction or ink-prediction payload
was opened. The [CT-only review](geometry/CT_REVIEW.md) finds useful crowded,
curved and void-boundary cases, but not the originally hoped-for balanced
four/easy-four/curved-four/difficult set. All cases remain; no replacements were
selected after looking at model scores.

**Reader v2 is executable in our retained runtime.** Its 138,382,373-byte released
checkpoint matches the publisher's SHA-256. All 508 tensors are finite; strict
loading has no missing/unexpected keys. The 34,546,498-parameter model passes two
bitwise-identical synthetic CPU forwards using its 17×128×128/MAD contract. This
is runtime compatibility, not author-output parity, accuracy, or GPU timing.
The saved step index is 39,999 for the publisher's 40,000-update artifact. Initial
environment/step-convention checks stopped before model execution; their receipts
are retained, and the active worker's environment was not modified.

The [baseline contracts](models/BASELINES.json) retain dense-native, both released
seed controls and Hecate. The [training specification](models/MATCHED_COVERAGE.md)
holds original-source draws and exposure fixed while changing added coverage.
Its actual cohort and GPU budget are not yet frozen. The Reader config exposes
99 representations, not 99 independent specimens. PHerc0343P is conservatively
grouped with PHerc0343; this is not a fresh independent Reader test parent.

**A prospective confirmation reserve now exists.** The entire PHerc0175 A/B
family (116 keV) and PHerc1203 (113 keV native plus its fine scan) are protected
from new development/training use. Only catalogue/header metadata was read.
The reserve protects all scans, aliases and derived teacher contexts; choosing
whole families avoids an unverified within-scroll registration exclusion.
They are absent from Reader v2's declared training config and marked F0-unseen
by the author registry, but m7/teacher/other-model ancestry remains unknown.
Independent labels and exact evaluation support are not ready. This is a
reservation, not an authenticated external benchmark. See the
[reserve review](registry/REVIEW.md).

## Next executable work

1. Use the native CT packet to define independently checkable same-sheet and
   different-sheet anchors and short trace paths. Verify what can actually be
   adjudicated; retain ambiguous cases. Add a predeclared easy positive control
   or explicitly revise the strata before a model comparison. The public
   instance pair supports metric development, not a substitute native reference.
2. Compare m7 and F0 with matched input/TTA/tracing when those references and
   execution contracts are ready. Separately compare tracers on the same field.
   The published m7 mask can be a cheap baseline, but differences in TTA/threshold
   must not be attributed to the training method.
3. Prepare the common-support native ink comparison using the now-qualified
   Reader v2 and retained strong models; keep the existing native0139 endpoint
   locked until its scheduled finish. Then finalize the matched coverage/data
   manifest and propose adequate GPU exposure rather than another tiny adapter.

No paid resource, Actions dispatch, new PR, spare-VM assignment or external
message was created. The first GPU pilot remains £10 total and requires explicit
approval of a concrete workload. The current native study is a baseline, not a
universal gate for these directions. No closed investigation was reopened.

## Evidence and portability

- Frozen source plans and exact source receipts are retained, including the
  public metadata review and all CT request hashes.
- `geometry/REFERENCE_INTAKE.json` selects the adjacent reference pair before
  payload acquisition. The later analysis freeze precedes decoding. A plotting
  dependency failure occurred before decoding; the revised implementation uses
  installed Pillow and leaves the metric/cohort unchanged.
- `geometry/CT_INTAKE_FREEZE.json` binds the native cohort, registry and exact
  raw CT byte budget before acquisition. `geometry/native-ct-review/RESULTS.json`
  records source verification and assembly, separately from visual judgement.
- `models/READER_QUALIFICATION.json` records checkpoint and runtime module hashes.
  Existing model pins are adopted from the completed study's receipts, not
  described as newly independently qualified here.
- [PORTABILITY.md](PORTABILITY.md) provides selective restoration and replay.
  The parent-family guard is an explicit check for new intake manifests, not a
  platform-wide interceptor. Future jobs must use it and maintain physical
  context/teacher exclusions when finer splits become available.
